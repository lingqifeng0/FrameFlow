# V18 拉伸绘制检查

日期：2026-10-11。版本 `7.1.2-modern.18`，EXE 文件版本 `7.1.2.1018`。

用户录屏中的问题发生在改变窗口高度、拖动上边或左上角时：当前蓝色标题栏已经移到新位置，旧的蓝色条或圆角碎片却短暂出现在视频下部。原来只隐藏了上下工具栏的内容，顶部蓝底仍然参与绘制；标题栏自身的裁剪区域也会随着每次宽度变化重建。

本版在开始拉伸后把顶部背景切换为与外框相同的深色 `#0D0F13`，隐藏上下栏内容，保留两栏原有高度。刷新深色占位后再修改窗口边界；拖动期间暂停标题栏圆角更新，并对窗口位置变化设置 `SWP_NOCOPYBITS`，避免旧客户区像素随窗口移动和缩放被复制到新位置。松开或失去捕获后恢复 `#0096FF`、标题栏圆角、窗口圆角和全部内容，自定义工具栏在最终宽度下排列一次。

原来的 16 个自定义槽位、按钮顺序、字体、图标、分隔线及设置继续使用。隐藏时不移除上下栏占用的空间，不会因为隐藏按钮额外扩大视频区域。普通窗口保留四边、四角拉伸；最大化和全屏继续使用原来的显示方式。

| 验证范围 | 结果 |
| --- | --- |
| 用户 GIF 检查 | 244 帧、约 24.4 秒；在第 181、201 帧确认视频下部出现蓝条与蓝色圆角残影 |
| Release 便携编译 | 成功，沿用项目已有的编译警告 |
| 配置与工具栏预算 | 103 项通过，包含 16 槽限制、旧配置保留、断点和不同宽度布局 |
| 标题栏控件绘制 | 8 项通过；连续 50 个宽度下，每一个标题栏像素都是深色，拖动状态不重建圆角，结束时只重建一次 |
| 实际鼠标拉伸 | Windows 175% 缩放；左上角、上边、左边三次实际拖动，1450×880 最终变为 1187×705；每次开始切换深色并暂停裁剪，松开恢复蓝色且只排列一次按钮 |
| 工具栏恢复位置 | 三次拖动后上下栏均处于客户区内，顶部位置为 (7,7)，未出现负坐标或图标区域移出窗口 |

| 窗口尺寸记忆 | 正常退出并在后台重开独立配置，1187×705 与原顺序的 16 个按钮全部保留 |
| 窄窗口 | 后台分别检查 820×620 的纯图标、显示文字布局；均保留 16 个按钮，多出的进入“更多”，直接按钮和“更多”无重叠、无裁切 |

桌面鼠标操作使用 Computer Use，状态通过独立测试播放器自己的公开 JSON IPC 订阅。后台重开检查不注入键鼠输入，使用 `SW_SHOWNOACTIVATE`。没有修改已安装播放器或其配置。测试记录在 `test-results/resize-v18`，主要是 `build.log`、`settings.log`、`rendering.log`、`icons/observations.json`、`release-checks.log` 与 `release-checks.json`。可复核的测试代码是 `tests/MpvNet.Chrome.Tests`、`tests/resize_rendering_audit.py` 和 `tests/resize_release_checks.py`。

本次实际鼠标验证覆盖上述三种拖动，未重新做全部八个方向的 GUI 回归，也未重复此前版本的全部全屏、插件跳转与音频端到端测试。控件逐像素绘制测试验证的是标题栏本身；原生窗口位置和拖动后的恢复由 IPC 与实际窗口截图交叉检查，不能将它等同于所有显卡、所有 DPI 的连续视频录制。

Win32 行为依据：[SetWindowPos 的 SWP_NOCOPYBITS](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos) 与 [WM_WINDOWPOSCHANGING 的 WINDOWPOS 可修改字段](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-windowposchanging)。保留 `WM_NCCALCSIZE` 原有的返回方式，以保持客户区子窗口对齐。

便携包为 `mpvnet-modern-V18-win-x64.zip`，内部仍为 `mpvnet-modern/mpvnet.exe`。包内只含出厂配置。更新时退出播放器，用新版程序文件替换旧文件，保留自己的 `portable_config`。

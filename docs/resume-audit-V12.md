# V12 共用断点与 Markdown 时间戳检查

日期：2026-10-11。结果：已修复并通过真实播放器回归。

## 确定的行为

同一配置下，每个视频在 `modern-ui.json / Positions` 中只有一份已保存进度。普通打开、MarkText 精确定位、手动拖动时间轴更新这份记录。Markdown 时间戳是固定锚点，点击它时优先；更新播放进度不会修改 Markdown。

多个窗口各自播放。最近打开、定位或从暂停继续播放的窗口更新该视频的断点，旧窗口的定时保存和退出保存不能覆盖它。不同视频的记录合并保存。UI 设置保存只合并本窗口修改的字段，不把启动时读到的断点整份写回。

## 实现

播放器初始化时停用原生 `watch_later` 自动恢复和退出保存，阻止旧原生起点在加载前覆盖共用进度。`on_load` 捕获显式起点和本次恢复策略，`on_preloaded` 只在未指定起点时采用共用断点。没有在 `file-loaded` 之后补发恢复 `seek`，没有使用固定延时再跳转。加载钩子和文件选项的时序依据 [mpv 官方手册](https://mpv.io/manual/stable/#hooks)，并通过真实播放内核验证。

读取最新保存的 `Positions`；只有缺少该视频记录时才导入旧原生历史。已经保存的零秒也是有效记录。老 `watch_later` 文件保留，不能反向覆盖共用记录。

`ResumeOwners` 保存随机写入标识，时间值仍只在 `Positions` 中。所有窗口通过同一路径的进程间锁更新 JSON，使用各自的临时文件原子替换，拒绝旧写入标识覆盖新进度。窗口打开、跳转、继续播放会取得新的标识，定时保存和退出保存不重新取得标识。

单实例注册使用完整 EXE 路径与配置路径，转发前核对 PID、进程启动时间、程序路径和主窗口所属进程。新消息使用带身份的 JSON，保留本次文件起点和播放状态等选项。接收窗口再次核对身份；没有可用目标时在本次进程打开。移除“一秒内打开就追加”的隐式规则。

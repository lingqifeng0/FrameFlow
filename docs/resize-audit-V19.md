# V19 拉伸背景与蓝色播放图标检查

日期：2026-10-11。版本 `7.1.2-modern.19`，EXE 文件版本 `7.1.2.1019`。

用户追加的 MP4 与截图显示：拉伸时除了旧蓝条，还存在黑色背景与外缘显示不完整、黑色条偏移的问题。V18 隐藏栏内容、切换深色并禁用旧像素复制，未安排每一次尺寸变化后的整窗即时重绘。不能用松开后的工具栏完整或标题栏单独的位图测试代替拖动过程验证。录屏左下角露出的彩色图是背后 Markdown 配图，本次不把它作为播放器旧视频残影的证据。

V19 将四边/四角的鼠标尺寸请求合并到 16 ms 的 UI 定时器，以最新位置为准。完成主窗 Dock 布局后调用 `RedrawWindow`，使用 `RDW_INVALIDATE | RDW_ERASE | RDW_ALLCHILDREN | RDW_UPDATENOW | RDW_FRAME`，整个客户区、边缘及嵌套子窗口立即更新。松开鼠标和失去捕获时先处理最后一个排队尺寸，再恢复蓝色圆角栏、窗口圆角和全部按钮。关闭时停止并释放定时器。没有添加整窗 `WS_EX_COMPOSITED`，视频继续使用原来的独立 GPU 窗口。

保留 V18 的 `SWP_NOCOPYBITS` 与客户区原有 `WM_NCCALCSIZE` 返回方式。拖动中不反复排列可编辑工具栏；松开时根据最终宽度排列一次。16 槽容量、按钮顺序、空白区无占位线、窄窗口“更多”和现有字体继续使用。

图标采用用户已预览并授权的 `#0096FF` 蓝色圆底、白色播放三角、透明外缘。原生 EXE 图标与 `MainForm.resx` 的图标同步；工具窗和设置窗使用同一个程序图标。ICO 包含 16、24、32、48、64、128、256 像素。文件关联注册入口为应用及每种文件类型补充 `DefaultIcon = <EXE>,0`，明确使用新的原生图标。本次只修改注册入口代码，没有运行它变更用户默认关联，也没有清空资源管理器缓存。

实际鼠标操作使用 Computer Use。连续测试只在自身进程内调用自身主窗方法，使用独立 `test-results` 配置，不注入键鼠、不操作其他软件。主窗状态由公开 IPC 与产品自身属性读取。测试记录在 `test-results/resize-v19`，可复现代码为 `tests/MpvNet.Chrome.Tests`、`tests/MpvNet.Resize.Integration`、`tests/resize_rendering_audit.py`、`tests/resize_release_checks.py` 和 `tests/icon_assets.py`。

本次测试曾在补齐原生组件前启动一次编译输出，弹出缺少播放组件的错误；该测试进程已退出，完整便携目录补齐组件后完成后续检查。连续测试还修正了测试读取的节点字符串需要二次 JSON 解码，以及重新构建文字按钮后需要刷新诊断状态的问题；这些属于测试程序，没有改变产品业务逻辑。

本机 GPU 测试通过，但没有覆盖所有显卡、所有显示器与 DPI，也没有将所有连续帧保存为桌面视频。中间栏的绘制样本、完整 HWND 重绘和坐标检查是三种不同证据，不将它们描述成逐帧的 DWM 合成截图。外部窗口、系统缓存和用户已安装播放器未修改。

Win32 行为依据：[RedrawWindow 的全区域、子窗口与即时更新参数](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-redrawwindow)、[SetWindowPos 的 SWP_NOCOPYBITS](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

便携包为 `mpvnet-modern-V19-win-x64.zip`，内部仍为 `mpvnet-modern/mpvnet.exe`。源码包同时包含修复和图标生成脚本。分发包排除本机断点、书签、窗口配置与渲染缓存。更新时保留原有 `portable_config`。
